# Reel Social Agent — project guide

Automated micro-documentary reel factory for @oneminutewtf. Read `docs/` first: `deep-research-report.md` (format + strategy), `pipeline-decisions.md` (architecture decisions), `pipeline-learnings.md` (hard-won generation rules). Those documents are the product spec.

## Layout

pnpm monorepo: `shared/` (Zod schemas + constants), `api/` (Fastify 5, port 4041), `frontend/` (Vite + React, 4040), `services/tts/` (Python Chatterbox, 4042, native not Docker), `services/captions/` (Remotion, 4043), `prompts/` (editable LLM prompt templates), `storage/` (generated media, gitignored).

## Hard rules (from docs/, do not violate)

- **Audio drives timing.** Beat durations come from ffprobe over the real TTS wav, never from script estimates. Clips are trimmed/padded to `audio + BEAT_GAP_SECONDS`.
- **A shot is not a beat.** A beat owns narration and timing; its picture time is filled by 1–6 SHOTS (`api/src/pipeline/shots.ts`, `planShots`). Cues, audio and overlays are per-beat and untouched by the split, so the `cues[i] ↔ beats[i]` invariant still holds — never push more than one cue per beat. Shot camera moves are ffmpeg `zoompan` (`buildShotArgs`), not Remotion. The plan is pure and deterministic because it goes into the merge content hash; **bump `SHOT_PLAN_VERSION` whenever the plan changes for unchanged inputs**, or the re-cut is silently skipped as already-done. `pnpm recut <id>` re-cuts any rendered video from assets already on disk for $0.
- **145 wpm rule.** `storyPost.postProcessStory` recomputes every word count and duration; LLM numbers are discarded.
- **Byte-identical style prefix** per video, injected server-side (`buildImagePrompt`); the LLM never writes style/negative boilerplate.
- **Motion prompts are motion-only** + fixed negative block (`MOTION_NEGATIVES`). **Action, not camera** — since 4 Sep 2026 every beat must move something in the frame (`motion.no_subject_motion`, error) and the camera clause is optional. Nothing forces `camera_locked` any more and `MOTION_LOCKED_CAMERA` is gone: "Absolutely no camera movement, tripod locked" was the loudest sentence in a prompt h3-max expands, and it came back as "a perfectly static shot throughout".
- **Every shot is its own generated clip.** Shot and clip are 1:1 (`api/src/pipeline/shots.ts`), each animating its own keyframe `variant`, because the reel has to be generated video throughout — a still with an ffmpeg `zoompan` move reads as a photo montage and was rejected on sight. The still path survives in `merge.ts` only as a fallback for a missing clip, and it publishes a `warning` naming the beats so it can never pass as a normal render. Clip windowing is gone for good: consecutive windows reproduce the take and overlapping ones dropped a reel from 21 detected cuts to 16.
- **Shot length is set by the model's billing floor.** `TARGET_SHOT_SECONDS` is 5.0 because h3-max will not accept under 5s; `MIN_SHOT_SECONDS` is a SCREEN floor and merge trims, so a 4.5s shot costs 5s. That ~16% waste is what buys the cut rate — measured on a 10-beat/80s reel: 18 shots at 4.47s mean, 96s billed, $7.68 fal + $0.70 stills = **$8.38**, against $8.07 for the old 10 shots of 8.4s. `clipSecondsFor` is the only place the waste is visible.
- **Idempotency by content hash.** Every asset row carries `content_hash = sha256(step inputs)`; steps skip existing hashes. Takes are never overwritten (`_v2`, `_v3`…).
- **Numbers as words** in narration ("nineteen eighty six"), digits break TTS.
- **Never transcribe our own TTS** — word timings come from forced alignment (`services/tts/app/align.py`, torchaudio MMS_FA) since the text is known.

## Backend conventions (mirrors claude-smart-memory)

- Three-file bootstrap: `index.ts` (process) / `app.ts` (`buildApp(config)`) / `config.ts` (`loadConfig()` — the ONLY place env is read).
- Routers are thin: schemas from `@reel-agent/shared`, SQL only in `database/queries/<table>.ts`, one file per table, `app` as first arg.
- Migrations: raw SQL in `api/src/database/migrations/`, `-- Up Migration` / `-- Down Migration`, `pnpm migrate`.
- Pipeline: BullMQ queue `pipeline`, worker in-process (`startWorker` in index.ts). Render chain: `tts → images → clips → merge → captions` (TTS first — clip lengths need real audio durations). Human gates (story approval, render review) are DB status changes from routes, not jobs.
- Progress: `publishEvent` → Redis pub/sub → SSE route `/api/videos/:id/events` (uses `reply.hijack()`; CORS header must be written manually there).
- Video state machine: `draft → story_review → approved → rendering → render_review → (publishing → published) | failed`.

## Tests

One `tests/` folder per service (`api/tests`, `frontend/tests`, `services/captions/tests`, `services/tts/tests`). api integration tests hit the real `reel-agent-test` DB (migrated in `tests/globalSetup.ts`) and real Redis, and obliterate the queue afterward. All external APIs are mocked; TTS tests stub the model (real synthesis behind `RUN_SLOW=1`).

## Gotchas

- pnpm blocks postinstall scripts unless listed in root `package.json` `pnpm.onlyBuiltDependencies` (esbuild is there — don't remove it).
- `services/captions` uses `moduleResolution: bundler` + extensionless imports because Remotion's webpack cannot resolve NodeNext `.js`-suffixed imports. Everything else is NodeNext with `.js` suffixes.
- The captions service streams the source video to Remotion's headless Chrome over its own `/files/` static route — the video path must live under `STORAGE_DIR`. First render downloads Chrome Headless Shell (~93MB).
- `fal.storage.upload` returns a bare 403 "Forbidden" for malformed/suspicious image files (verified: a hand-crafted 100-byte PNG is rejected, a real PNG uploads fine) — `FalClient.uploadImage` falls back to a base64 data URI on any upload error, so the pipeline survives either way.
- fal clips are whole seconds at 24fps with a PER-FAMILY floor (`minDurationSeconds` in the caps table, not a hardcoded 5); merge re-encodes to 30fps CFR and trims — never assume the clip length equals the request. Verified output for a 5s 768P h3-max request: 768×1344, ~5.18s. Everything upstream is 768×1344 and merge upscales to 1080×1920, so the stills are the resolution bottleneck for any punch-in (`ImageConfig.imageSize` defaults to `1K`; `2K` is available).
- fal e2e verified 1 Sep 2026 through the production client: upload → queue submit → status poll → download all work with the current key.
- Chatterbox is not thread-safe; the TTS service serializes generation with a lock and the pipeline calls it with concurrency 1. Cold model load ~90s on MPS.
- A long-idle TTS process can wedge (instant 500 on every /synthesize; observed 1 Sep 2026 after ~15 min idle on macOS — suspected App Nap / MPS state). A restart fixes it. Mitigations in place: TtsClient retries once after 5s, and the service returns real exception details instead of a bare 500. If it recurs, restart via `pnpm dev:tts`.
- **`gemini-2.5-flash-image` accepts `imageConfig.imageSize` and silently ignores it** (verified 3 Sep 2026: `1K` and `2K` both return 768×1344 at an identical 1290 image tokens). Only the gemini-3 image models honour it — `gemini-3.1-flash-image` and `gemini-3-pro-image` return 1536×2752 at `2K`, with 2.1–3.7x the measured high-frequency detail. That headroom is what a shot's camera move zooms into, so `GEMINI_IMAGE_SIZE` is only worth setting alongside a gemini-3 model. Per-image prices (Google's pricing page, 3 Sep 2026): 2.5-flash $0.039, 3.1-flash @2K $0.101, 3-pro @2K $0.134, 3.1-flash-lite $0.0336 (1K only). Update `GEMINI_IMAGE_COST_USD` whenever `GEMINI_IMAGE_MODEL` changes — nothing derives it.
- **A beat has SEVERAL stills, one per shot** (`assets.variant`, migration `1788480000000_asset-variant`). Variant 0 is canonical: the fal clip animates it and the kicker's end frame is edited from it. `insertAsset`/`nextTakeNumber`/`findAssetByHash` are all variant-scoped, because deselecting by `(video_id, kind, beat_index)` alone would make a beat's second still deselect its first. **Anything doing `new Map(assets.map(a => [a.beat_index, a]))` over keyframes silently keeps only the last variant** — `merge.ts` groups them into arrays, `clips.ts` filters `variant === 0`. Variants share the beat's `image_prompt` verbatim; separate generations of one described scene are different compositions of the same moment, which is what a second angle should be.
- Gemini free tier has **zero** quota for image models (`generate_content_free_tier_requests, limit: 0` → 429 on every call) — billing must be enabled on the key's Google Cloud project before Nano Banana works. Plain-auth calls (models list) succeed, so a 200 on /models does NOT prove image generation will work. `gemini-2.5-flash-image` currently resolves to `gemini-2.5-flash-preview-image` server-side.
- Telegram `sendMessage` fails with 403 "the bot can't send messages to the bot" when TELEGRAM_CHAT_ID is the bot's own id — the chat id must be the human's id from @userinfobot, and the human must have pressed Start in the bot chat.
- BullMQ requires `maxRetriesPerRequest: null` on its ioredis connection.
- **Ollama can wedge like the TTS service does** — observed 2 Sep 2026 timing out at 120s on a one-field request with a one-field schema, while `/api/ps` still reported the model resident. `OllamaProvider` now carries a 15-minute deadline (it previously had none, unlike the claude/codex providers); if it recurs, `ollama stop <model>` then restart the app. `qwen3.6` is also a reasoning model: a trivial reply took 112s because of the thinking pass, so budget minutes per story, not seconds.
- **fal request fields come from the caps table, never from memory.** `api/src/clients/falModels.ts` carries the schema-verified shape of every endpoint we have checked: the first-frame field NAME (Kling v3 says `start_image_url`, not `image_url` — a wrong name is a 422 exactly like a wrong field), `durationType` (Kling and Seedance take duration as a STRING enum), `minDurationSeconds` (h3-max 5s, Kling 3s, Grok 1s — this is the real floor on shot length), `hasNegativePrompt`, `supportsResolution` (Kling v3 has no resolution field at all) and `audioField`. **`generate_audio` defaults TRUE on Kling and Seedance** and merge strips clip audio — on Kling that default is a **+50% surcharge for something discarded**, so `fal.ts` always sends it false. `pnpm fal:schema <id>` prints a paste-ready caps block; it also flags `prompt_optimizer` and `auto_fix` as rewrite mechanisms, because hailuo-2.3 reported "no rewrite" while `prompt_optimizer` defaulted to true.
- **Seedance 2.5 was priced and rejected 4 Sep 2026 — do not re-research it.** `bytedance/seedance-2.5/image-to-video` is real and well-behaved (4–30s, no prompt rewriting, `end_image_url`, `image_url`), but it is **token-billed**: `(h × w × duration × 24) / 1024` tokens at $0.0214/1k (480p/720p) or $0.0234/1k (1080p). At 720p vertical that is **$0.462/s → ~$30 for a 65s reel**, and 1080p vertical is **$1.137/s → $74**. Worse, its 720p vertical output is **720×1280, LOWER than the 768×1344 h3-max already delivers**, and fal does not list 1080p vertical as supported. Six times the price for fewer pixels; the only thing it buys is motion physics. Seedance 2.0 fast is $0.2419/s and 2.0 standard $0.3024/s, both also above h3-max.
- **h3-max pricing was promotional.** 768P was $0.02/s until **7 Sep 2026** and $0.08/s after; `FAL_COST_PER_SECOND_USD=0.04` was wrong in both directions. The caps table records post-promo, per-resolution rates — over-reporting spend is safe, under-reporting it 4x is not. Verified 3 Sep 2026: Kling v3 standard $0.084–0.154/s, pro $0.112–0.196/s, Grok Imagine $0.05/s at 480p, Seedance 2.0 fast $0.2419/s.
- **`FAL_MAX_CLIPS_PER_VIDEO` is EMPTY by default and should stay that way.** Empty = no cap: every SHOT gets its own generation and the reel is generated video throughout. A number caps it and the uncapped shots fall back to a still with an ffmpeg camera move — that shipped once (video 14, ~90% stills, $2.84) and was rejected on sight as a photo montage. Treat it as an emergency spend brake, not a setting; 0 = stills only. `shotsForClips` spends a tight cap on the hook first, then the turn or reveal. An explicit `beatIndexes` from `/upgrade-clips` bypasses it on purpose. **Clip windowing is a dead end, tried and measured:** consecutive windows of one clip reproduce the take (zero cuts), and overlapping ones dropped a reel from 21 detected cuts to 16, because a cut inside near-continuous film is not a cut.
- **fal's `minimax/h3-max/image-to-video` rewrites our motion prompt.** `prompt_expansion_mode` is a REQUIRED field defaulting to `balanced`, and the rewrite comes back as `expanded_prompt` — recorded in `generation_runs.output`. Read it before tuning any motion rule; the model does not generate from the text we send. The same endpoint accepts `seed` (never echoed back, so we derive it via `seedFromHash`) and `end_image_url` (used for the loopable kicker), and has no `negative_prompt` — `MOTION_NEGATIVES` must stay in the prompt text. Verify any endpoint with `pnpm fal:schema <id>` before repointing `FAL_VIDEO_MODEL`; pricing is NOT in the openapi document.
- Craft rules are enforced by the `STORY_RULES` registry in `api/src/utils/storyValidate.ts`, not by prose. Adding a rule without a case in `api/tests/storyValidate.test.ts` fails the registry meta-test on purpose. Rule ids are persisted in `videos.story_findings`, so `rule` is `z.string()` and never a `z.enum`.
- Prompt examples rotate: `HOOK_EXAMPLE_POOL` in `shared/src/craft.ts` is sampled per topic, and `story.example_leakage` errors if a story copies one. **Every illustrative sentence in `prompts/story.user.md` must be wrapped in backticks** — that is how `storyPromptExamples()` finds them; never backtick a line the model is supposed to copy (capture-medium lines, shot-type prefixes).
- TikTok integration exists but is parked (see README). Do not delete `clients/tiktok.ts` / the publish step; they are the planned next phase.
- Model ids are env-configurable and move fast (docs §1 of pipeline-learnings) — never hardcode a model name outside config defaults.
- **Narration pace is produced after synthesis, not by Chatterbox settings.** The house preset (cfg 0.3) delivers 182–194 wpm; the TTS service splits each beat into sentences with a 0.35s gap and time-stretches (ffmpeg `atempo`, pitch kept, floor 0.8x) to `TTS_TARGET_WPM` (152; 145 was judged a touch slow by ear). Pace params ride on the request and sit in the audio content hash (`TTS_PRESET_VERSION`). Calibrate for free with `pnpm tts:calibrate`. Envelope is 50–70s / 120–150 words / 7–10 beats (150 words = 62s speech + ~7s gaps, so the word count is the control); `BEAT_GAP_SECONDS` is 0.6. Measured: the calibration paragraph went 215 → 150 wpm, video 8's narration 182 → 145; most beats hit the 0.8 floor. **The running TTS process is whatever code it was started with** — restart `pnpm dev:tts` after touching `services/tts/app`, and `/health` reports `target_wpm` so you can tell.
- **A lexicon cannot gate a mandatory-motion rule.** Tried twice now, recorded so it is not tried a third time. Gating `motion.no_subject_motion` on `SUBJECT_MOTION_VERBS` errored **4-7 beats of every story** in the Opus 5 corpus on prompts that plainly described action: `haul` is not an alias of `hauling`, `rolls back` is not an alias of `rolling`, and "steam creeps out and spreads over the concrete" matched nothing. The rule now asks the question it cares about — **is the camera the only thing moving?** — by stripping camera clauses and counting what is left (camera-only leaves 0 words, real action 6-15). The clause splitter MUST break on `while` and `as` as well as punctuation, or a shared clause like "Both men feed sticks into the fire as the camera tilts up" reads as camera-only; and bare `frame` must not count as a camera cue, because "grips the frame" is a car's frame. All of those are pinned as regression cases in `storyValidate.test.ts`. Corpus result: **1 true positive in 7 stories, 0 false.**
- **Faces are wanted, addressing the lens is not.** The prompt permitted people and then taught the opposite with three averted examples ("a back turned to the event", "hands on a rail"), so the model generalised the `MOTION_NEGATIVES` ban on turning to camera into no faces at all. `prompts/story.user.md` now asks for a five-part PERSON SPEC — age band and build, one garment by fabric and cut, one tool in use, what the hands are doing, which side of the face is lit — and states the distinction outright. `image.human_presence` wants a person in most beats (was: any beat); `image.face_visible` warns when no beat lights a face. `MOTION_NEGATIVES` is unchanged: a figure swinging to the lens mouthing nothing is still the clearest tell.
- **`MAX_HOOK_IMAGE_PROMPT_WORDS` is 60 and PROVISIONAL.** It was 45, derived before the person spec existed; a compliant hook now runs ~48 words and the acceptance fixture's is 47. The rule's discriminating power is weaker than it was, because a person spec legitimately spends the words that used to signal extra subjects — re-derive it from a fresh eval rather than trusting the number.
- **People are allowed in frame since 2 Sep 2026** (docs/visual-style.md §7). Never corpses/injury (`image.graphic_content`, error), never a real named face (`image.named_likeness`), always the on-screen `AI RECONSTRUCTION` tag plus TikTok's AI-generated label. The hook must show the event, never paperwork (`image.hook_is_document`), and must move (`motion.hook_locked`).
- **Mean motion cannot tell a camera move from real action; peak÷mean can.** `measureAction` returns both, and `generation_runs.output.action_ratio` records the ratio. Measured: real generated clips **31-35** (video 4's hook, the best performer, 79 and 241), an ffmpeg pan over a still **14-24** — while the MEANS were indistinguishable (5.71 vs 5.91). `clips.ts` warns below 22. Diagnostic, never a gate: the sample is 14 clips.
- **Measure the clip, not the prose describing it.** `measureMotion` (`utils/ffmpeg.ts`, ffmpeg `tblend`+`signalstats`, ~1s per clip, free) records mean inter-frame luma difference into `generation_runs.output.measured_motion`. It is **diagnostic and must not become a gate**: across all 36 clips of the four published reels it ranged 1.0–7.6, and video 4 — the best performer at ~20% AVD — had the LOWEST value in the batch, so a threshold would have rejected the one hook that worked. `expansionFlags` no longer flags mood words (`tranquil`/`serene`/`peaceful`/`calm`): that false positive is what led `docs/retention-postmortem-and-change-plan.md` §3.1 to name fal as the primary cause of the retention failure, when video 9's hook expansion actually describes "a continuous, steady truck right … functioning as a tracking shot". A locked beat is never flagged at all — our own prompt tells it to hold still, twice.
- **`FAL_PROMPT_EXPANSION_MODE` defaults to `quality`.** Under `balanced` the rewrites flattened real motion into "Static Shot … small amplitude"; `clips.ts` flags such rewrites as `expansion_flags` in `generation_runs.output`.
- **Never run Ollama from an agent session.** A `qwen3.6` (23 GB) prompt eval exhausted the laptop and killed the session on 2 Sep 2026. `pnpm prompt:eval` defaults to Claude Code Haiku (cents per story); Ollama is hidden on the Generate page (`GeneratePage.tsx`, the API provider still exists). After a validator edit, `pnpm prompt:rescore` re-scores the stories already saved in `api/eval-out/` for free — use it before paying for another eval.
- **A lexicon term used in the wrong SENSE is the recurring validator bug.** Three instances so far: bare `grain` (material, not film), `tranquil` in `expansionFlags` (scenery, not motion), and `bleeding` in `GRAPHIC_CONTENT_TERMS` — the Opus 5 eval caught "rust bleeding down the fence post" erroring on **3 of 5** stories, at ERROR severity, so each bought a second paid provider call for exactly the wear detail `image.imperfection` demands. The fix pattern differs by stake: narrow the list where a false negative is cheap (`grain` → `film grain`), but STRIP the wrong sense where a false negative is expensive (`GRAPHIC_CONTENT_EXCLUSIONS` + `stripPhrases`, because this rule guards against a policy strike). `remains`, `bodies` and `drowning` are the same class of latent risk and have not fired yet — do not pre-emptively narrow them without eval evidence.
- **`hook.tension_marker` has no measured discriminative power.** It fires on **5/5** Opus 5 stories (a 19-word keyword list cannot cover the ways English states an anomaly — it flags "Rat poison carried the Olympic marathon winner"), and it PASSED video 7's hook, the worst published performer. It is a warning so it costs nothing but attention; a findings list that always fires trains the producer to ignore it. Left in place pending a craft decision, not a bug fix.
- **`image.hook_legibility` (warning) is calibrated, not guessed.** A FULLY COMPLIANT hook prompt is ~38 words once `prompts/story.user.md`'s mandated clauses are all present (shot type, subject, a human, one light source with a direction, an atmosphere cue, one imperfection) — the good fixture's is exactly that. `MAX_HOOK_IMAGE_PROMPT_WORDS = 45` sits above it, so what the rule catches is extra SUBJECTS: Opus 5's five hooks ran 54-74 words and the longest names nine distinct objects. Word count is a proxy for "things in frame", hence tier 2 and warning-only.
- **Opus 5 high via cursor-agent costs ~$0.58 a story** (measured 3 Sep 2026, 2-call budget) and ~29 min for a 5-topic eval. `EVAL_PROVIDER=cursor-agent EVAL_MODEL=claude-opus-5-high RUN_EVAL=1 EVAL_N=5 pnpm prompt:eval`. **vitest only prints stdout for FAILING eval cases**, so the per-topic histograms of the passing ones never appear — the stories are all saved to `api/eval-out/` regardless, and `pnpm prompt:rescore` is how you read them. Note rescore prints DISTINCT warnings, not counts: a rule listed once may have fired on one beat of nine.
- **Validator lexicons are two lists, on purpose.** `SUBJECT_MOTION_VERBS` (curated, purpose-tagged) feeds the once-per-video reuse rule; `GENERIC_MOTION_VERBS` (detection only) feeds `story.subject_motion_count` and `motion.hook_locked`. The curated list alone under-counted real motion ("runners stagger forward") and errored good Haiku stories into paid retries. Camera aliases must not match a subject's action ("pushes forward" was a false `push_in`), and verb aliases collide with nouns ("floor cracks"), so a repeated subject verb is a warning and only a repeated camera move is an error. The pov shot prefix is `point of view` (not `… from`) because Haiku writes "point of view shot".
- **`shared/` changes are invisible to api tests until `pnpm --filter @reel-agent/shared build`** — vitest resolves `@reel-agent/shared` to `dist/`, so a green typecheck with red tests reading `undefined` from shared is a stale build, not a bug.
- **Rule id renames are safe, rule severity changes are not free.** `image.people` became `image.graphic_content` without a migration (ids are `z.string()`); turning `story.subject_motion_count` into an error made every violating story cost a second Opus call, so a new error rule has to be checked against saved eval stories first.
- **TikTok AIGC rules (Community Guidelines, Sep 2025):** realistic AI people are allowed when labelled; removed regardless of label are real private likenesses, misleading public-figure depictions, "dead bodies", "the moment of someone's death" and AIGC that "misleads about a crisis event". Hence the on-screen `AI RECONSTRUCTION` tag (`RECONSTRUCTION_TAG`, `CAPTION_STYLE_VERSION` 4) and the AI-generated toggle at post time.
- **A row action inside the dashboard's row `<Link>` is invalid markup.** Each production-queue row is an anchor, so the delete button is a flex SIBLING of the link, not a descendant — nested inside it the markup is invalid and a click both deletes and navigates. `DashboardPage.test.tsx` pins `button.closest('a')` as null. Delete itself was never broken: the route, the query and all four `ON DELETE CASCADE` foreign keys work (dry-run verified against a 24-asset video); the dashboard simply had no control to click.
- Music is added inside TikTok at post time — do not propose a music/ambience step.
- **`cursor-agent` is the third CLI provider and the only one whose model is per-request.** Verified 2 Sep 2026 against `2026.08.31-4057e58`: `-p … --output-format json --mode ask --trust` prints ONE `{"type":"result",…,"result":"<text>","usage":{"inputTokens":…}}` line (usage is camelCase); on failure it prints nothing to stdout, writes to stderr and exits 1, so an execa throw IS the error path. **`stdin: 'ignore'` is load-bearing** — with an open stdin pipe the CLI emits the envelope and then hangs forever waiting for EOF, exactly like `codex exec`. It runs in an empty scratch dir (`storage/.cursor-agent`) on purpose: from the repo it would index the codebase and fold `AGENTS.md`/`.cursor/rules` into the story prompt. `--system-prompt <file>` exists but is gated to "Anysphere/OpenAI team only". The ask-mode system prompt alone costs ~20k input tokens per call, so a cheap model is not free. **Usage splits the prompt across `inputTokens` and `cacheReadTokens`** — the same 21617-token prompt sent twice reported 21617/0 then 2302/19315, so reading `inputTokens` alone under-counts a warm call to near zero; `promptTokens()` sums both cache buckets and cost prices each bucket separately. **A Cursor model is a base model plus parameters**, not a flat id: the 217 ids `--list-models` prints are 35 base models x effort x thinking x fast, and the picker mirrors Cursor's own (short model list grouped into its billing pools — Grok and Composer are the in-subscription `cursor` pool — then only the parameters that model has). The grid is RAGGED (Composer has no effort rungs, Gemini no fast tier, `gpt-5.5` spells extra-high as `extra-high` where everyone else says `xhigh`), so ids are always looked up in the catalogue, never composed from strings — a built id that does not exist is a CLI error. `shared/src/cursorModels.ts` is GENERATED — refresh with `pnpm cursor:models`, never hand-edit — and cost is estimated per family prefix in `api/src/llm/cursorPricing.ts` (longest prefix wins: `claude-4.6-opus` needs its own row or it bills as a Sonnet) because Cursor reports tokens but no dollars.
- **Every `LlmStorySchema` constraint must either be stated in the prompt or normalized away in `postProcessStory`** — a cap the model can't know about is a paid schema retry (observed: an undocumented 48-char `evidence_stamp` cap burned two codex calls). Only Ollama has schema-constrained decoding; the CLI providers return whatever the prompt earns. Story generation is budgeted at **2 provider calls max** (`runStoryGeneration` — one attempt + one unified repair/rewrite retry), a valid first draft always survives a broken retry, and failed attempts persist the raw model output in `generation_runs.output.raw`.

## Verification

`pnpm typecheck && pnpm test` at root, `pytest` in `services/tts`. End-to-end: generate a story with Claude Code, Codex or Cursor Agent (never Ollama, see gotchas), approve it, watch the pipeline strip; a full real render costs ~$3–5 (fal + Gemini).

Prompt quality has its own tooling, all free:

- `pnpm prompt:eval` — generates real stories through Claude Code Haiku (default; a few cents each) and prints the finding histogram per topic. Stories are saved to `api/eval-out/`; `pnpm prompt:rescore` re-runs the current validator over them for free. Run it before and after any prompt edit and diff the histograms; that comparison, not a single sample, is what tells you whether a change helped. Gated behind `RUN_EVAL=1` and never in CI.
- `pnpm prompt:critique` — read-only review of `prompts/` plus the direction docs by Codex (`gpt-5.6-luna`) and Claude (Opus), written to `docs/prompt-critique-<date>.md`. Act on what both models raise; treat a single-model finding as a hypothesis.
- `pnpm cursor:models` — regenerates `shared/src/cursorModels.ts` from `cursor-agent --list-models`. Free (a local catalogue read, no inference). Run it when a model you expect is missing from the Generate page picker; it re-derives the base-model list and the effort/thinking/fast grid, so a new Cursor family becomes selectable with no code change.
- `pnpm recut <videoId>` — re-cuts an already-rendered video under the current shot planner from the clips and stills already on disk. Free, ~20s of ffmpeg, and takes are never overwritten so the previous cut survives as the control. This is how a cut-rate change is measured without paying for a render.
- `pnpm fal:schema <endpoint-id>` — the real input/output schema and capabilities of a fal endpoint, from the public openapi document. Run it before repointing `FAL_VIDEO_MODEL`; a guessed field is a 422.
